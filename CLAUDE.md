# CLAUDE.md

Rules and conventions for working in this repo. For overview, architecture, and quickstart see @README.md. For env vars see @.env.example.

## Commands

```
npm run dev          # tsx with 8GB heap, the normal dev loop
npm run build        # tsc to dist/
npm run typecheck    # tsc --noEmit, run before claiming a task is done
npm test             # node --test dist/**/*.test.js (build first)
pwsh scripts/run-bot.ps1   # supervisor loop for unattended runs
```

Python trainer (separate venv in `training/`):
```
cd training && python train_dqn.py   # tails data/online/, rewrites models/policy.onnx
```

## Critical conventions

**IMPORTANT: One session per process.** `bedrock-protocol` leaks internals on reconnect and OOMs after ~30 min. `index.ts` exits with code 10 on any disconnect and `scripts/run-bot.ps1` restarts with a fresh heap. Do not add in-process reconnect logic.

**IMPORTANT: `POLICY_MODE` selects exactly one controller.** They are mutually exclusive, not stacked. In `online`/`learned`/`explore` the GOAP main loop is disabled and the 100ms ML tick in `agent.ts:afterSpawn` drives the bot. In `shadow` GOAP drives and ML only logs labels. Do not write code that assumes both run together.

**IMPORTANT: All outbound packets go through `safeQueue`.** Bedrock packet schemas drift between versions; one missing field must not crash the bot. Never call `client.queue()` directly.

**Version-conditional fields are gated by `detectVersionFlags`** (`src/connection/version.ts`). Do not assume `analogue_move_vector`, `dynamic_container_id`, or subchunk-request mode exists across versions.

**Sticky actions are load-bearing.** `POLICY_STICKY_MS` (default 400ms) holds each policy action across multiple 100ms ticks. Without it the InputController never keeps a movement bit set long enough and the bot looks frozen. If you change tick rates, recheck this.

**`item_stack_request` request IDs must be odd, negative, and unique.** See `src/crafting/request_id.ts`. Bedrock rejects even or repeating IDs.

**2x2 crafts skip the container open dance.** `RecipeRegistry.findByOutputName(name, preferNoTable=true)` biases toward the no-table variant (+100 score). 3x3 crafts walk to a crafting table and open it via `src/crafting/container.ts`.

**Recipe network IDs come from the server `crafting_data` packet on join.** Do not hardcode them; they differ across BDS versions.

**`prismarine-chunk` defaults to Bedrock 1.21.0 palette tables.** Newer servers may need `client.options.version` overridden or runtime IDs map wrong.

**`models/policy.onnx` is hot-reloaded.** `LearnedPolicy.watchForReload` polls mtime every 5s and swaps the session when size is stable across two polls. The trainer must export via atomic rename (`*.tmp` then `rename`), never partial-write the live file.

**`intent.ts` is a one-way side channel.** GOAP writes its current primitive with `setIntent`; the trajectory logger reads it via `readIntent` so shadow mode can label trajectories without instrumenting every GOAP action. The learned policy does not touch it.

## Cross-language invariants

**YOU MUST keep these in sync between TS and Python:**
- `OBS_DIM = 605` (`src/ml/encoder.ts` and both `training/train_*.py`)
- `ACTION_COUNT = 16` and the ActionId enum order (`src/ml/actions.ts` **and** `src/ml/policy.ts` (separate literal to avoid the import cycle), and trainer output dim). Ids 0-11 are movement/mine/place/attack/eat; 12-15 are the craft macros (planks, sticks, crafting_table, wooden_pickaxe).
- Observation layout: self[0..8), grid[8..413), entities[413..445), inv-slots[445..509), inv-bag[509..601), tree[601..605)
- Trajectory JSONL schema: `{obs_b64, obs_len, action, reward, t, meta?}`. `obs_b64` is base64 of the raw Float32Array buffer.

Changing the obs or action space without updating both sides is a silent data corruption bug; the trainer happily learns garbage.

## When making changes

- **New GOAP action**: implement in `src/goap/actions/`, register in `actions/index.ts`, add to `IMPLEMENTATIONS` in `goap/executor.ts`.
- **New packet handler**: bind in `src/world/perception.ts` (or appropriate `attach*`). Handlers MUST be attached before `waitForSpawn`.
- **New primitive ML action**: update `ActionId` enum, `DIR_YAW`, `executeAction` switch, bump `ACTION_COUNT` in **both** `src/ml/actions.ts` and `src/ml/policy.ts`, add to Explorer weights, update `N_ACTIONS` in both `training/train_*.py`.
- **UI/frontend or user-facing prose**: no em dashes, no AI buzzwords (`leverage`, `robust`, `delve`, `comprehensive`, `moreover`). Plain dev voice. This applies to README, this file, code comments, and any public-facing docs.

## Not in git

`data/online/` (rollouts, hundreds of MB), `models/*.onnx` (regenerated by trainer), `node_modules/`, `dist/`, `*.log`, `.env`, `.claude/`. The repo ships with no model file; first launch in `online` mode runs the Explorer until one exists.
